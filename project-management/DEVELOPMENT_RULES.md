# SoloMate – Development Rules

## 1. General Rules

- Complete assigned tasks before the deadline.
- Update the Master Project Tracker daily.
- Work only on assigned modules.
- Inform the Project Lead about blockers and delays.
- Do not modify another member's module without approval.

## 2. Technology Stack

- Mobile Application: Flutter
- Web Application: Angular
- Backend: ASP.NET Core (C#)

## 3. Architecture Rules

- Follow the approved project architecture.
- Follow Clean Architecture and DDD principles.
- Maintain separation between Domain, Application,
  Infrastructure and Presentation layers.
- Follow MVVM principles where applicable.
- Reuse existing shared components.
- Obtain approval before adding new dependencies.

## 4. GitHub Rules

- Never push directly to the main branch.
- Create and use assigned feature branches.
- Write meaningful commit messages.
- Submit a Pull Request for every completed task.
- Obtain Project Lead approval before merging.

## 5. UI/UX Rules

- Follow approved UI designs.
- Maintain consistent colors, typography and spacing.
- Ensure all visible buttons and navigation work.
- Clearly distinguish mock data from real backend data.

## 6. Testing Rules

- Test all implemented features.
- Fix build errors before submitting.
- Validate user journeys and input fields.
- Provide screenshots and testing evidence.

## 7. Security Rules

- Never commit passwords, API keys or access tokens.
- Protect confidential project information.
- Follow authentication and authorization requirements.

## 8. Task Completion Rules

- Complete the assigned implementation.
- Update task progress in the tracker.
- Submit the GitHub Pull Request link.
- Resolve review corrections.
- Obtain final Project Lead approval.

## 9. Final Deadline

30 November 2026

All team members must follow these development rules.
